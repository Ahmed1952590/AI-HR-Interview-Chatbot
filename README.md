# AI HR Interview Chatbot Platform

AI-powered HR interview practice (WEX428 project). Candidates choose a job role, experience level, difficulty and
categories; the system picks questions by **semantic similarity** using Sentence-BERT embeddings stored in **FAISS**.
No external LLM API is used anywhere.

| Layer | Technology |
|---|---|
| Frontend | React + TypeScript (Vite), React Router, Recharts |
| Backend | FastAPI (Python), SQLAlchemy, JWT, BCrypt |
| NLP | sentence-transformers (`all-MiniLM-L6-v2`), FAISS |
| Database | SQLite by default (set `DATABASE_URL` for PostgreSQL) |
| Deployment | Docker + Docker Compose, Nginx reverse proxy |

## Run it locally (development)

Requirements: Python 3.10+ and Node.js 18+. The first run downloads the Sentence-BERT model (about 90 MB), so you need internet once.

**1. Backend** (terminal 1)
```bash
cd backend
python -m venv venv
venv\Scripts\activate            # Windows   |   source venv/bin/activate  (Mac/Linux)
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```
API docs: http://localhost:8000/docs

**2. Frontend** (terminal 2)
```bash
cd frontend
npm install
npm run dev
```
Open http://localhost:5173

**3. Log in as administrator and import the data**

Default admin: `admin@example.com` / `Admin123!` (change with the `ADMIN_EMAIL` and `ADMIN_PASSWORD` environment variables).

1. Dataset (250,000 questions): unzip `data/demo_dataset_250000.zip` and upload the CSV. It is **synthetic**, generated by `python backend/scripts/make_demo_dataset.py` (24 roles, 10 categories, 3 levels, 3 difficulties), not the university dataset. Embedding 250,000 questions takes roughly 10-60 minutes on CPU, so start it early. Use the optional **Row limit** (e.g. 2000) for a quick test.
2. Official university dataset (about 250,000 questions): when you have it (CSV or JSON), upload it the same way. Duplicates are skipped, so you can add it on top or delete the demo dataset first with the delete button.
3. Register a normal candidate account (or log out and use **Create an account**), and start an interview.

## Run with Docker

```bash
docker compose up --build
```
Open http://localhost:3000 (API: http://localhost:8000/docs). Data, the database, the FAISS index and the model cache live in `./data`.
Set `SECRET_KEY`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` in a `.env` file for anything other than a demo.

## Run the tests

```bash
cd backend
pip install -r requirements-dev.txt
pytest
```
The tests use a tiny fake embedder (no model download, no internet) and cover registration/login/logout/reset, role protection,
CSV/JSON import with duplicate detection, FAISS storage, the full interview flow (answer, skip, ideal answer, finish, history, no repeated
questions), question/category/user management, analytics and CSV export. GitHub Actions runs them on every push (`.github/workflows/ci.yml`),
together with the frontend type-check and build.

## Show the semantic search (useful for the defense)

```bash
cd backend
python scripts/semantic_demo.py --role "DevOps Engineer" --experience Fresher --difficulty Easy --category Adaptability
python scripts/semantic_demo.py --text "how do you handle sudden change at work" --role "DevOps Engineer"
```
In the admin panel, tick **Search by meaning** on the Questions page to search the whole dataset by meaning instead of keywords.

## How the NLP part works

1. **Import** (`services/importer.py`): validate columns, skip duplicate questions, store keywords, embed every question with Sentence-BERT in batches, append the vectors to the FAISS index (`data/faiss.index`) and remember each question's position (`vec_idx`).
2. **Retrieval** (`services/retrieval.py`): filter candidates by role, experience, difficulty and category, embed a query built from the interview setup, rank candidates by cosine similarity using the FAISS vectors, and return the most similar unseen question (FR-4). The query is the interview setup plus the candidate's latest answer, so the next question follows the conversation and sessions differ naturally. `RETRIEVAL_TOP_K` (default 1) can be raised to pick randomly among the best few. Near-duplicates (similarity above 0.92) of earlier questions are skipped too. If nothing matches, filters are relaxed step by step (category, then difficulty, then experience); the role is always kept.
3. Ranking uses Maximal Marginal Relevance (`MMR_LAMBDA = 0.7`): relevance to the interview setup, minus similarity to questions already asked, so the interview stays varied.
4. With several categories selected, the interview rotates through them.

## REST API (all in `/docs`)
Auth: `POST /register /login /logout /forgot-password /reset-password`, `GET /validate-token` ·
User: `GET/PUT/DELETE /profile`, `PUT /profile/password`, admin `GET/PUT/DELETE /users` ·
Interview: `POST /interview/start`, `GET /interview/question`, `POST /interview/answer /skip /finish`, `GET /interview/ideal/{id} /history /stats /{id}` ·
Questions: `GET/POST /questions`, `PUT/DELETE /questions/{id}`, `GET /questions/semantic` ·
Dataset: `POST /dataset/upload`, `GET /dataset/status`, `DELETE /dataset/{id}` ·
Analytics: `GET /analytics`, `GET /analytics/export` ·
Categories/roles: `GET/POST/PUT/DELETE /categories` and `/roles`, `GET /options`

## Notes
- Forgot password has no mail server: the reset token is shown on screen (demo mode).
- Logout revokes the token in memory (it resets when the backend restarts).
- Interview tips are rule-based (STAR method, category hints, keywords), because the dataset has no tips field.
